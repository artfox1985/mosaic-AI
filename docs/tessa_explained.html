How Tessa Thinks

Tessa is a program that plays a tile-laying board game (a private re-creation of Azul Duel) against people, and nobody ever told it a single strategy. This page shows what happens inside the computer when Tessa makes a move, and how it learned to play. No formulas, but at the level where it actually runs.

The two parts

A gut feeling and a calculator

Tessa is made of two parts that need each other.

The network is an artificial neural network: a large table of numbers that settled into place during training. Show it a position and it answers at once with two things: which moves look good? and how good is the game for me? The network calculates nothing. It recognizes patterns, like an experienced player who looks at the board and has a feeling.

The search actually tries moves out: play a move, play the opponent's reply, keep going, and at the end ask the network how the resulting position looks. It does that four hundred times per move. The search corrects the gut feeling; the gut feeling tells the search where trying is worth it.

Stage 1 · What the network sees

The board becomes numbers

A network cannot see a board, only numbers. So every position is translated first: each cell of the 6 x 6 dome is described in 79 layers (which color lies here, which color may still go here, which cell scores a bonus, and so on). On top come 888 single numbers for everything that is not on the board: the factory displays, the penalty track, the scores, the round, the three active scoring tiles.

From this wall of numbers the network computes two answers:

  1. Move choice: for each of the 414 conceivable moves a number between 0 and 1, "how promising". Illegal moves are masked out beforehand.
  2. Evaluation: one number between 0 and 1, the probability of still winning this game.

This answer takes a fraction of a millisecond. But it is only a feeling: the network has not tried any of the moves.

Stage 2 · What the search does

Four hundred times "what if"

Now the calculator. The search takes the network's suggestions and tries them out, but not all of them equally thoroughly. This is how one move runs:

  1. Pick candidates. Out of the 414 moves the search takes the 16 with the best network values, with a small pinch of randomness so it is not always the same ones.
  2. Try. For one candidate it plays the move, then the most likely reply, then its own move again, a few moves deep. At the end it asks the network: "how good is it here?" That is one attempt.
  3. Halve. After a round of attempts the weaker half of the candidates is dropped. The rest get more attempts. This repeats: 16, 8, 4, 2.
  4. Add up. After 400 attempts every candidate has an average evaluation of everything that was tried behind it. The best one is played.

All of this takes a fraction of a second per move. A full game with both sides playing at this level takes about 16 seconds on the project machine.

Why not just calculate everything? A game has dozens of moves with up to a hundred options each. The number of possible games is larger than the number of atoms in the universe. The search gets by with 400 attempts only because the network tells it beforehand where trying pays off.
Stage 3 · Where the learning comes from

The gap between feeling and calculation is the lesson

This is the part that makes the whole thing learn. Before the search starts, the network has already made its guess: "move A 0.38, move E 0.23, ...". After 400 attempts the search has its own verdict, from actually trying: "move A got 61 % of the attempts, move E 21 %, move C 9 %".

Put the two side by side and three things can happen:

  1. They agree. The network guessed what the search confirmed. There is nothing to learn from this position; the correction is close to zero.
  2. They disagree. The network liked move B, the search found it does nothing. The difference between the two is exactly the correction that training applies to the network: push B down, pull A up. The bigger the surprise, the bigger the step.
  3. The search is worse than the feeling. This can happen when the search gets too few attempts. Then the "lesson" is noise, and training makes the network worse. The project ran into exactly this: with 100 attempts per move the network's evaluation stopped improving at all. At 400 attempts it improved again.

The same idea holds for the evaluation. The network says "62 % win"; the game is then played to the end and either won or lost. The distance between the guess and the actual outcome is the second correction.

Why this never stops paying. Every time the network closes the gap, the search starts its 400 attempts from better suggestions, so its verdict gets better too, and the gap opens again at a higher level. Feeling and calculation pull each other up. The project measured where this stops: when the net's end-of-round guesses were checked against the exact result, the remaining surprise was close to zero. There was nothing left for a deeper search to correct.
Stage 4 · The training loop

Play against yourself, write it down, adjust, prove it

Nobody showed Tessa what a good move is. The network starts with random numbers and plays badly. Even so, the search in front of it is already a little better than the bare network, because it tries things. That difference is the teacher, and this is the loop it runs in:

  1. Self-play. The program plays thousands of games against itself, both sides with search. For the last generation that was 16,000 games, each with 400 attempts per move.
  2. Write it down. At every move it stores the position, how often the search tried each candidate, and in the end who won.
  3. Adjust. In training, the numbers in the network are shifted step by step so that its move choice gets closer to the search's distribution and its win chance closer to the actual outcome. Twelve passes over all positions, about half an hour on the graphics card.
  4. Prove it. The new network plays the reigning champion, 400 games per run, always both colors from the same starting conditions. Only if the lead is statistically certain does it become the new champion.

Then it all starts over, with the better network playing the self-play games. The project ran 35 such generations.

Stage 5 · The proof

Why one win proves nothing

Two programs that both play well often beat each other only narrowly. Whoever wins 55 of 100 games may simply have been lucky. So the proof is built to be strict:

  1. Every game is played twice, once with the sides swapped, with the same factory displays and scoring tiles. Nobody can draw "good cards".
  2. Games are counted in blocks of five pairs, and across the blocks it is calculated whether the lead is larger than what chance alone would explain.
  3. If the lead is clear early, the proof may stop. It is then repeated to the end with a fresh set of starting conditions.

Tessa beat its predecessor 289 games to 161 (64 percent) and confirmed it in the repeat with 249 to 151. On the project's Elo ladder it stands at 1660; a fixed rule-based reference player defines the 1000.

The most surprising lesson of the last generation: the biggest step did not come from a smarter network or a deeper search, but from which games the network was allowed to learn its move choice from. When all self-play games were admitted as teaching material instead of a third of them, the win rate against the old champion rose from 57 to 64 percent.
